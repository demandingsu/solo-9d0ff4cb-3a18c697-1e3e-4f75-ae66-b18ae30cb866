# 农技语料双人盲标系统

FastAPI + SQLite 的田间病虫害描述双人盲标网页应用。每条记录由**两名不同标注员**
独立标为 **病害 / 虫害 / 无异常**，两票一致才进入训练集下载。支持按**农户号**
管理数据来源与撤回使用许可。

## 功能规则

| 规则 | 实现 |
| --- | --- |
| 上传语料 | UTF-8 CSV，表头 `record_no,description,farmer_no`（或 `记录号,描述,农户号`），**每行必须带农户号** |
| 三名标注员 | 内置 标注员甲/乙/丙，页面右上角一键切换（cookie 记录身份） |
| 双盲 | 提交前服务端不返回他人标签：待标页只显示票数，标注页只有描述 |
| 领取时效 | 每次领取有效 **60 秒**（`CLAIM_TTL_SECONDS` 可调），过期可重新领取 |
| 重领作废旧页 | 重新领取会轮换凭证 token，**即使同一人**，旧页面提交一律拒绝 |
| 重复提交 | 同人同版本重复提交不加票（数据库主键 + 事务内判重） |
| 描述改写 | 同号描述有改动 → 版本 +1，**同事务清除旧领取与旧标签**，迟到提交无法写入新版 |
| 未变重传 | 同号描述未变 → 保留全部领取与标注进度（农户号必须与库内一致） |
| 农户撤回 | 按农户号撤回：同事务清除其记录、领取、标签，并持久封禁该号 |
| 封禁拦截 | 含封禁农户号的 CSV **整批拒绝**；封禁记录号不得改绑；原描述换号重传按指纹拦截 |
| 旧库升级 | 无农户号的旧记录与标签保留，页面标为「来源未知」，不得擅自归到某农户 |
| 训练集下载 | 仅含**当前版本两票一致**的记录：`record_no,description,label`（撤回农户的数据已物理删除） |
| 双进程共享 | 两个应用进程挂载同一 SQLite 文件（WAL），并发领取/提交/改写/撤回串行化、不破坏约束 |
| 重启保留 | 标签、领取期限与封禁名单全部落库，容器重启不丢 |

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

compose 启动三个容器：

- `app1` / `app2`：两个相同的应用进程，挂载同一命名卷 `dbdata`，共享 `/data/annotate.db`；
- `gateway`：nginx 轮询反向代理（`:8080`）。刷新页面，页脚的"服务进程"会在
  app1 / app2 间切换——领取在 app1、提交落在 app2 也照常工作。

首次启动空库时自动导入仓库内置样例 `sample_data.csv`（8 条田间描述，4 个农户号）。

## 浏览器演示

### 1. 双人盲标 → 下载训练集
1. 右上角切换到 **标注员甲**，待标页点「领取并标注」，60 秒倒计时内点「病害」；
2. 切换到 **标注员乙**，领取同一条（页面看不到甲的标签），也点「病害」；
3. 「可用」页出现该记录（带农户号），「下载训练集」得到 `train_labels.csv`；
   若两人标签不同，记录进入「分歧」页且不会下载。

### 2. 农户撤回使用许可
1. 打开导航栏 **撤回许可**，输入样例中的农户号 `F-0001`（名下 T-0001、T-0003），确认撤回；
2. 撤回成功后回到 **待标 / 可用 / 分歧** 页与「下载训练集」：该农户的记录全部消失，
   其领取与标签一并清除，**封禁名单**页可查到该号及被清除的记录号；
3. 到 **上传 CSV** 页尝试以下文件，都会被**整批拒绝（一行不入库）**：
   - 含 `F-0001` 的新 CSV（封禁农户号）；
   - 沿用其记录号 `T-0001` 但农户号改成别人（记录号不得改绑）；
   - 把原描述原文配上新记录号、新农户号（描述指纹拦截，防止换号重传）。

### 3. 超时重领
1. 任一人领取一条记录，**不提交**，等倒计时归零（页面按钮自动禁用）；
2. 强行提交 → 「领取已过期，本次提交被拒绝」；
3. 回到待标页重新领取（拿到新凭证），**回到旧页面提交 → 仍被拒绝**（凭证无效）；
4. 用新页面提交 → 成功；再点一次 → 「重复提交已忽略」，票数不增加。

> 想缩短等待，可在 `docker-compose.yml` 把 `CLAIM_TTL_SECONDS` 改成 `"10"` 再启动。

### 4. 改写后旧页提交
1. 标注员甲领取记录 `T-0005`（停留在标注页，先不提交）；
2. 修改 `sample_data.csv` 里 `T-0005` 的描述（农户号列保持 `F-0002` 不变），在「上传 CSV」页上传
   → 提示"改写 1 条（旧领取与标签已清除）"；
3. 回到甲的旧标注页提交 → 「领取凭证无效 / 提交被拒绝」，新版记录不会被旧页写入；
4. 原样再传一次同一文件 → 提示"未变保留"，已有进度原样保留。

### 5. 双进程与重启
- 刷新页面看页脚进程名在 app1/app2 间切换，所有状态都在共享库中；
- `docker compose restart app1 app2` 后：已标记录、封禁名单仍在，未过期的领取仍可提交
  （期限按绝对时间计算，重启不重置）。

## 旧库升级（来源未知）

升级前已存在的 SQLite 库没有农户号列，应用启动时自动 `ALTER TABLE` 补列：

- 旧记录与其领取、标签**原样保留**，`farmer_no` 为 NULL，各列表页显示黄色标签
  「来源未知」，训练集下载规则不变；
- 系统不会把来源未知的记录归到任何农户名下：上传同号记录并指定农户号会被整批拒绝；
- 来源未知记录不参与按农户号撤回（没有农户号可撤回），如需移除请由管理员另行处置。

## 架构与并发设计

```
app/                 应用包
  main.py            FastAPI 路由（页面渲染 + 表单动作）
  logic.py           业务规则：领取 / 提交 / 上传预检与改写 / 农户撤回 / 列表查询
  db.py              SQLite 连接（WAL + busy_timeout）、建表与旧库迁移、BEGIN IMMEDIATE 写事务
  templates/ static/ 服务端渲染页面
sample_data.csv      内置样例（空库自动导入，含农户号列）
docker-compose.yml   app1 + app2（共享卷）+ nginx 网关
tests/               规则测试与多线程并发测试（含撤回/上传交错）
```

- **一致性**：所有"检查 + 写入"都在 `BEGIN IMMEDIATE` 事务内完成，SQLite 写锁
  使两个进程的并发操作串行化；上传先做**整批预检**，任一违规则事务回滚、一行不落库；
  撤回事务中途失败同样整体回滚，原状态保持不变。
- **撤回**：单事务内依次快照记录号与描述指纹（sha256）→ 删除标签/领取/记录 →
  写 `banned_farmers`。旧领取随删除失效，并发的迟到提交只会拿到"凭证无效"。
- **三道上传防线**：封禁农户号（`banned_farmers`）、封禁记录号改绑
  （`banned_farmer_records`）、原描述换号（`banned_descriptions` 指纹）。
  描述指纹可能误伤与撤回农户描述完全相同的其他农户文本，这是为保证"田间描述退出
  训练集且不得换号重传"刻意选择的保守策略。
- **领取**：`claims` 表 `UNIQUE(record_no, version, annotator)`，重复领取
  `UPSERT` 轮换 token——旧页凭证随之失效；提交时校验 token → 版本 → 过期时间。
- **改写**：清领取、清标签、版本 +1 在同一事务；旧 token 随领取一起被删。
- **盲标**：标注页/待标页不输出任何他人标签，仅显示票数；分歧页只在两票齐后可见。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DB_PATH` | `data/annotate.db`（容器内 `/data/annotate.db`） | SQLite 文件路径 |
| `CLAIM_TTL_SECONDS` | `60` | 领取有效期（秒） |
| `SEED_ON_EMPTY` | `1` | 空库时是否导入样例 |
| `SEED_CSV` | `sample_data.csv` | 样例 CSV 路径 |
| `INSTANCE_NAME` | 主机名 | 页脚显示的进程名 |

## CSV 格式

```csv
record_no,description,farmer_no
T-0001,玉米叶片出现黄褐色梭形条斑，病斑边缘有黄色晕圈，疑似大斑病,F-0001
```

- 三列均为必填，缺列或缺农户号的行会导致整份文件被拒绝；
- 新记录号 → 新增（v1）；同号描述改变 → 版本 +1 并清旧数据（农户号须与库内一致）；
  同号描述不变 → 跳过；
- 同一文件内重复记录号按顺序处理（后者视为改写），但同号绑定不同农户号直接整批拒绝；
- 下载的训练集带 UTF-8 BOM，Excel 直接打开不乱码。
